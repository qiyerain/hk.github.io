AI 项目重点

1. alibaba/open-code-review

语言与热度：Go；41,057 Stars；本周 +6,920。

解决的问题：大变更容易漏文件、评论位置漂移，完全依赖自然语言技能时质量不稳定。

核心亮点：读取 Git diff，按规则选取文件并关联上下文，再调用可配置模型生成精确到行的结构化评论；ocr scan 还可以审计没有明显 diff 的完整目录。README 的 AACR-Bench 说明强调更高精确率和更低 token 消耗，同时明确召回率更低，这是主动取舍。

适用人群与落地场景：维护多人代码库的团队，可先选一个已有人工结论的 PR，对照文件覆盖、评论定位和误报率。

2. stablyai/orca

语言与热度：TypeScript；77,834 Stars；本周 +6,547。

解决的问题：多个 Agent 同时改同一个目录时，上下文和未提交改动互相干扰。

核心亮点：每个 Agent 使用独立 Git worktree，可并行跑五个方案，再比较并合并胜者；桌面端和移动端还能继续跟进任务。

适用人群与落地场景：需要比较实现方案的工程师。先选一个边界清楚的小任务，保留人工合并和完整测试。

3. affaan-m/ECC

语言与热度：JavaScript；267,149 Stars；本周 +6,193。

解决的问题：一次提示词无法长期维持计划、测试、评审、记忆和安全检查。

核心亮点：将 skills、instincts、memory、hooks 和安全扫描组合为可复用的 Agent 工程系统，并覆盖多个编码助手。

适用人群与落地场景：已有智能体开发流程的团队。先挑一条测试或评审链路接入，确认各平台能力是否对齐。

4. Tencent/WeKnora

语言与热度：Go；29,877 Stars；本周 +3,749。

解决的问题：企业文档分散，问答、推理和知识维护难以共享同一个事实底座。

核心亮点：把 RAG、Agent 和 Wiki 放在同一知识库上，支持混合检索、多模态解析、引用、知识图谱与回滚，并可对接多种数据源。

适用人群与落地场景：需要私有化知识问答和文档运营的团队。先拿一组有明确答案的内部资料验证引用质量与更新流程。

5. addyosmani/agent-skills

语言与热度：JavaScript；98,955 Stars；本周 +3,345。

解决的问题：Agent 项目容易跳过规格、测试和复核，交付质量依赖个人习惯。

核心亮点：用 /spec、/plan、/build、/test、/review、/ship 等命令映射完整生命周期，把质量门槛变成可重复的技能。

适用人群与落地场景：希望让团队 Agent 遵循共同工程规范的开发者。先从一个仓库的 review 或 test 命令开始。

本周最值得看

代码审查以读取变更、规则匹配、Agent 深审和行级反馈组成工作流

open-code-review 最值得拆开看。它没有把所有审查步骤都交给模型：文件选择、关联分组、规则匹配和评论定位适合程序化约束；需要理解上下文和判断风险的环节才交给 Agent。这样做的价值是让结果更容易复查，而不是承诺“自动审查不会漏掉问题”。

最小试用方式是准备一个已知缺陷和误报样本的 PR，比较它是否找对文件、评论是否落在正确行、漏掉了哪些问题。不要只看它生成了多少条评论。

趋势观察

审查： 从“让模型看看代码”走向确定性流程约束，先保证覆盖和定位，再让 Agent 做动态判断。

协作： 并行 Agent 的价值不只是多开几个窗口，而是用 worktree 隔离上下文，并保留可比较的合并面。

知识： RAG 不再只是问答组件，文档解析、引用、记忆、Wiki 和 Agent 工具开始共享同一套知识底座。

交付： skills 把规格、计划、测试和复核变成团队可重复执行的命令，减少“会生成但不会交付”的断层。
