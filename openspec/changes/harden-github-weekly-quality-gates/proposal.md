# Harden GitHub Weekly Quality Gates

The weekly workflow produced a readable article only after manual correction, while the first browser state showed a blue low-contrast body, one cover had been stretched between platform ratios, and the issue was absent from the GitHub trends collection because its category did not match the generator contract.

This change adds deterministic content, visual, browser, and collection checks to the existing weekly automation without changing its schedule or publication authorization.

## Scope

- Pin weekly posts to the readable Style Pack A and canonical collection category.
- Require browser verification after the build, including contrast and image geometry.
- Require native platform-cover ratios and evidence-bearing body infographics.
- Require rendered collection verification.
- Preserve the existing WeChat draft-only safety and idempotency rules.

## Impact

- The current 2026-10-23 article Front Matter.
- Project-level GitHub weekly guidance in `AGENTS.md`.
- Automation `github` prompt and memory.
- No schedule, model, publishing permission, or unrelated site styling changes.
